# แขน 2 ข้าง + คอ ด้วยสเต็ปเปอร์ ผ่าน ESP32

วันที่: 2026-11-10

## ทำไม

ให้น้องทานตะวัน-Bot ขยับแขน 2 ข้างและหันคอได้จริง (แทนแขนเซอร์โว PCA9685 เดิมใน `robot/web/arm.py`)
Raspberry Pi เป็นคนตัดสินใจท่าทาง (ทักทาย โบกมือ หันหาคน) ส่วน ESP32 รับคำสั่งแล้วสร้างพัลส์ขับสเต็ปเปอร์ให้นุ่มและแม่น
— Pi ทำงานหลายอย่าง (เว็บ AI เสียง) สร้างพัลส์เองไม่นิ่ง

## ฮาร์ดแวร์ (เจ้าของกำหนด)

- ESP32 1 ตัว · สเต็ปเปอร์ 17HS4401S 3 ตัว (1.8°/สเต็ป, 1.7A) · ไดรเวอร์ TB6600 3 ตัว
- **ไม่มีลิมิตสวิตช์** (เจ้าของยืนยัน)
- เพิ่มเอง: แหล่งจ่ายไฟ 24V ≥ 5A สำหรับมอเตอร์ (ห้ามใช้ร่วมกับ Pi) · สาย USB Pi ↔ ESP32

## การต่อสาย

```
Raspberry Pi ──USB──► ESP32 ──STEP/DIR/EN──► TB6600 ×3 ──► 17HS4401S ×3
                                               ↑ 24V แยก
```

| แกน | ชื่อในโปรโตคอล | PUL+ | DIR+ | ENA+ |
|---|---|---|---|---|
| แขนซ้าย | `L` | GPIO 25 | GPIO 26 | GPIO 13 (ร่วม) |
| แขนขวา | `R` | GPIO 27 | GPIO 14 | GPIO 13 |
| คอ | `N` | GPIO 32 | GPIO 33 | GPIO 13 |

- ต่อแบบ common-cathode: `PUL-` `DIR-` `ENA-` ของทุก TB6600 → GND ของ ESP32
- TB6600 DIP: microstep 1/8 (1600 สเต็ป/รอบ), กระแส 1.5A
- สัญญาณ 3.3V ถ้า TB6600 รับไม่นิ่ง → เพิ่ม 74HCT245 แปลงเป็น 5V (ไม่ต้องแก้โค้ด)

## โปรโตคอล (USB serial 115200, ASCII ทีละบรรทัด `\n`)

รูปแบบ: Pi ส่ง `#<id> <คำสั่ง>` → ESP32 ตอบ `#<id> OK ...` หรือ `#<id> ERR <code> <ข้อความ>`
`id` = เลข 1–65535 ที่ Pi ตั้ง (จับคู่คำตอบกับคำสั่ง)

| คำสั่ง | คำตอบ | ความหมาย |
|---|---|---|
| `PING` | `OK fw=<ver> parked=<0/1>` | เช็กการเชื่อมต่อ + ต่ออายุ heartbeat |
| `MOVE L=<deg> R=<deg> N=<deg> [V=<deg/s>]` | `OK` แล้ว `#<id> DONE` เมื่อทุกแกนถึง | ขยับไปมุมสัมบูรณ์ แกนที่ไม่ระบุอยู่ที่เดิม; ทุกแกนเริ่ม/ถึงพร้อมกัน |
| `POS?` | `OK L=<deg> R=<deg> N=<deg> busy=<0/1>` | ตำแหน่งปัจจุบัน |
| `STOP` | `OK` | หยุดแบบชะลอทันที (คำสั่ง MOVE ที่ค้างได้ `#<id> ERR STOPPED`) |
| `EN <0/1>` | `OK` | ปลด/ล็อกแรงบิด |
| `ZERO` | `OK` | ตั้งตำแหน่งตอนนี้เป็น 0 ทุกแกน + ล้าง `NOT_PARKED` |
| `PARK` | `OK` แล้ว `DONE` | กลับ 0 ทุกแกน → ปลดแรงบิด → จด "จอดแล้ว" ใน NVS |

ข้อความที่ ESP32 ส่งเองได้ (ไม่มี id): `EVT BOOT parked=<0/1>`, `EVT WATCHDOG` (หยุดเพราะ Pi เงียบ)

รหัส error: `BAD_CMD` `BAD_ARG` `LIMIT` (เกินมุมที่ตั้ง) `NOT_PARKED` (ยังไม่รู้ตำแหน่ง) `BUSY` `STOPPED`

## ความปลอดภัย (ทำใน ESP32 ไม่พึ่ง Pi)

- **มุมจำกัดต่อแกน** (ค่าเริ่ม แขน −10°…180°, คอ −60°…60°) — เกินตอบ `ERR LIMIT` ไม่ขยับ
- **ตำแหน่งเริ่มต้นโดยไม่มีลิมิตสวิตช์:** NVS เก็บธง `parked` (ตั้งหลัง `PARK` เสร็จ, ล้างทันทีที่เริ่ม `MOVE`)
  เปิดเครื่องแล้ว `parked=1` → ตำแหน่ง = 0 ใช้งานได้เลย / `parked=0` → ทุก `MOVE` ตอบ `ERR NOT_PARKED` จนกว่าจะได้ `ZERO`
- **Heartbeat:** ระหว่างขยับ ถ้าไม่ได้รับคำสั่งใด ๆ นาน 3 วินาที → หยุด + `EVT WATCHDOG` (Pi ส่ง `PING` ทุก 1 วิตอนมอเตอร์ทำงาน)
- เร่ง/ชะลอด้วย AccelStepper (ไม่กระตุก ไม่ข้ามสเต็ป)

## ฝั่ง Pi

- `robot/web/stepper.py`: คลาสคุย serial (หา `/dev/ttyUSB*`/`ttyACM*` เอง, ส่ง/รอคำตอบตาม id, heartbeat, ไม่มี ESP32 = โหมดจำลองแบบ `arm.py`)
- ท่าทาง (`wave`, `greet`, `look_left/right`, `park`) เขียนเป็นลำดับ `MOVE` ใน Python แก้ได้ไม่ต้องแฟลช ESP32
- `/greet` เดิมเรียกท่าโบกมือของสเต็ปเปอร์แทนเซอร์โว · ตอนปิดเซิร์ฟเวอร์/ปิดเครื่อง สั่ง `PARK`
- หน้าครู `/stats`: ปุ่ม "ตั้งตำแหน่งศูนย์" (ส่ง `ZERO`) + แถบเตือนเมื่อ ESP32 แจ้ง `NOT_PARKED`

## ไม่ทำ

- ลิมิตสวิตช์ / หา home อัตโนมัติ (เจ้าของไม่เพิ่ม)
- ควบคุมผ่าน Wi-Fi/Bluetooth (ใช้ USB เส้นเดียว)

## ปล่อยให้คนทำตัดสินใจ

- โครงสร้างโค้ดเฟิร์มแวร์ (Arduino IDE หรือ PlatformIO), ค่าความเร่ง, มุมของแต่ละท่า
- อัตราทด: ค่าเริ่มต่อแกนตรง (1:1); ถ้ามีเฟือง/สายพาน แก้ค่าคงที่ `STEPS_PER_DEG` ต่อแกน
