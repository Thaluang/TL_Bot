# จอ 1920 แบบใหม่ + ข่าวประชาสัมพันธ์จากหน้า stats

วันที่: 2026-11-10 · ภาพอ้างอิง: `.superpowers/brainstorm/kiosk-news-mockup-v3.html` (เจ้าของยืนยันแล้ว)

## ทำไม

คนเดินผ่านหุ่นหน้าวิทยาลัยเห็นจอ 1920 (จอสัมผัส) ทีมอยากให้จอนี้เป็น "บอร์ดประชาสัมพันธ์ที่คุยได้"
ฝั่งซ้ายโชว์เวลา อากาศ และข่าวเด่นที่ครูลงเอง ฝั่งขวาคุยกับหุ่น
ครูลงข่าว (รูป + ข้อความ) จากคอมห้องธุรการผ่านหน้า stats โดยไม่ต้องแตะไฟล์ในเครื่อง

## เป้าหมาย

1. หน้า `/screen` ใหม่ตาม mockup v3 แทนหน้าเดิมทั้งหมด (ลบแถบซ้าย/หน้าต้อนรับกลางจอ/โหมดมืดของเก่าออก)
2. หน้า `/stats` มีแท็บ "ข่าวประชาสัมพันธ์": เพิ่ม/แก้/ซ่อน/ลบ/เรียงลำดับข่าว ใส่รูป ตั้งวันเริ่ม–หมดอายุ ต้องใส่รหัสก่อนแก้
3. ข่าวที่ลงขึ้นจอภายใน 1 นาที และหุ่นตอบคำถามเรื่องข่าวนั้นได้
4. ข้อมูลข่าว/รูป/สถิติอยู่รอดหลังรีบูต (เก็บบนแฟลชไดรฟ์ USB)

## ไม่ทำ (รอบนี้)

- หมุดชี้ตำแหน่งห้องบนแผนผัง (เจ้าของตัดออก)
- โหมดมืด
- ให้ครูสร้างหมวดข่าวเอง (มี 5 หมวดตายตัว)
- จอ 7" (`/face`) ไม่เปลี่ยน

## ห้ามพลาด (ถ้าเป็นแบบนี้ = ล้มเหลวแม้โค้ดรันได้)

- ฟีเจอร์เดิมหายไป: ไมค์ (`/stt` สำรอง), พิมพ์ + คีย์บอร์ดบนจอ (`osk.js`), เครื่องสแกน QR USB, เมนูที่เที่ยว/ของฝาก,
  แผนผัง, ทัวร์ 3 มิติ, เปิดลิงก์ในหน้า, ให้ดาว, ปุ่มหยุดพูด, ประกาศตามเวลา, ทักทาย + โบกแขน, สลับภาษา TH/EN, sync สถานะไปจอ `/face`
- ครูที่ไม่รู้รหัส (หรือใครก็ได้ในวง Wi-Fi) แก้ข่าวได้
- เขียนไฟล์ลง rootfs ของการ์ด SD (การ์ดปลอม — เขียนแล้วพัง) หรือเขียนรูปขนาดเต็มจนแฟลชไดรฟ์เต็ม
- เดโมบน GitHub Pages (`web/demo`, `build_demo.py`) พัง

## ข้อจำกัด

- Pi 4 รันแอปจาก RAM (`/dev/shm/tlbot`, แตกจาก `/boot/firmware/tlbot/app.tar.gz` ทุกบูต) — แอปเขียนพาร์ทิชัน boot ไม่ได้ (root)
- จอ 1920×1080 แนวนอน จอสัมผัส ILITEK, Chromium kiosk บน Wayland (labwc)
- Wi-Fi หลุดบ่อย → ฟอนต์ Google ต้องมีสำรอง (ฟอนต์ระบบ) และหน้าจอต้องไม่ค้างถ้าดึงอากาศไม่ได้
- ไม่มี Node บนเครื่องพัฒนา, ทดสอบด้วย pytest (Flask test client) อย่างเดียว
- Python ฝั่ง Pi ไม่มี Pillow แน่นอน → ย่อรูปที่ฝั่งเบราว์เซอร์ของครู (canvas) ก่อนอัปโหลด

## ส่วนที่ตัดสินใจแล้ว

### ที่เก็บข้อมูล (เจ้าของเลือก: แฟลชไดรฟ์)
- โฟลเดอร์ข้อมูล = ค่า `TLBOT_DATA_DIR` ถ้าตั้ง; ไม่ตั้ง = หาแฟลชไดรฟ์ที่ desktop เมานต์ให้เองใต้ `/media/<user>/*/` แล้วใช้ `<ไดรฟ์>/tlbot-data/`;
  ไม่เจอ = `robot/data/` (เครื่องพัฒนา Windows) — หน้า stats แจ้งเตือนถ้ากำลังใช้ที่เก็บชั่วคราว (RAM)
- เก็บในโฟลเดอร์นั้น: `news.json`, `news/<id>.jpg`, `stats.db` (ย้ายสถิติมาด้วย — ตอนนี้หายทุกรีบูต)

### ข่าว
- ฟิลด์: id, หมวด (`admission|event|scholarship|award|general`), หัวข้อ, บรรทัดล่าง, รายละเอียด, ลิงก์ (ไม่บังคับ → QR), รูป (ไม่บังคับ),
  วันเริ่ม, วันหมดอายุ, ซ่อน (bool), ลำดับ
- จอแสดงเฉพาะข่าวที่ไม่ซ่อน และวันนี้อยู่ในช่วงเริ่ม–หมดอายุ เรียงตามลำดับ (บนสุด = ข่าวเด่น)
- ชุดละ 3 ข่าว (ข่าวเด่นรูปเต็ม + 2 การ์ดเล็ก) มีหลายชุดสลับทุก ~10 วิ; แตะการ์ด = หุ่นอ่านหัวข้อ+รายละเอียด
- ไม่มีข่าวเลย = การ์ดเชิญชวน "ถามน้อง TL-Bot ได้เลย" แทน
- หุ่นรู้ข่าว: ข่าวที่ขึ้นจออยู่ต่อท้ายข้อมูลที่ส่งให้ AI (ใช้กลไกเดียวกับข้อมูลวิทยาลัย และล้างแคชคำตอบเมื่อข่าวเปลี่ยน)

### หน้าครู
- ใส่รหัสครั้งเดียวต่อเบราว์เซอร์ (`ADMIN_PASSWORD` ใน `.env`, ไม่ตั้ง = ปิดการแก้ข่าว) → เซิร์ฟเวอร์ออก token เก็บใน cookie
- ดูสถิติไม่ต้องใส่รหัส (เหมือนเดิม)
- รูป: เบราว์เซอร์ย่อเหลือด้านยาวไม่เกิน 1600px JPEG ~0.82 ก่อนส่ง; เซิร์ฟเวอร์รับไม่เกิน 3 MB และต้องเป็น JPEG/PNG/WebP จริง

### จอ 1920
- ซ้าย: นาฬิกา + วันที่ไทย (พ.ศ.), อากาศ (Open-Meteo ผ่านเซิร์ฟเวอร์ `/weather` แคช 30 นาที, พิกัดท่าหลวง สระบุรี; ดึงไม่ได้ = ซ่อนการ์ด),
  ข่าวเด่น
- ขวา: หัวหุ่น (หน้าตาเรืองแสง) + สถานะ + TH/EN, แชท, ชิป 4 อัน (สมัครเรียน/หลักสูตร/แผนผัง/ที่เที่ยว), ช่องพิมพ์ + "เมนูทั้งหมด", ปุ่ม "แตะเพื่อพูด"
- แผนผัง / รูปสถานที่ / เมนูที่เที่ยว-ของฝาก / เมนูทั้งหมด → ขึ้นแทนข่าวฝั่งซ้าย (มีปุ่มกลับ + กลับเองเมื่อว่าง 60 วิ)
- ทัวร์ 3 มิติ / ลิงก์ภายนอก ยังเปิดเต็มจอแบบเดิม
- วิดีโอ: หน้าข่าวเป็นหน้าหลัก ว่างครบ `IDLE_VIDEO_SECONDS` (เปลี่ยนค่าเริ่มเป็น 180) → เล่นวิดีโอ 1 คลิปแล้วกลับหน้าข่าว + เริ่มคุยใหม่; ไม่มีวิดีโอ = ไม่แทรก
