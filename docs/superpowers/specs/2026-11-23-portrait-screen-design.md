# จอสัมผัสแนวตั้ง (Portrait kiosk) — ดีไซน์

วันที่: 23 พ.ย. 2569 · เส้นตาย: ประกวดระดับภาค ต้นเดือน ธ.ค. 2569
ม็อกอัปที่อนุมัติ: `docs/superpowers/specs/portrait-mockup/index.html` (ภาพ `home.png`)

## ทำไม
จอสัมผัสของหุ่นจะตั้งเป็นแนวตั้งแบบตู้บริการ (kiosk) ผู้ใช้อยากให้หน้าแรกเป็น "ระบบบริการอัจฉริยะ One Stop Service"
ตามโปสเตอร์ตัวอย่าง — คนเดินมาเห็นเมนูบริการของวิทยาลัยทันที และคุยกับหุ่นได้จากปุ่มเดียว
ต้องดูทางการ น่าเชื่อถือ และ **ใช้ได้จริงตอนกรรมการลองกด**

## เป้าหมาย
- หน้าใหม่ 1080×1920 ย่อ/ขยายพอดีจอ หน้าตาตามม็อกอัป (น้ำเงินเข้ม-ทอง, หัวเป็นกรอบสี, ไอคอนเส้น **ห้ามใช้อีโมจิ**)
- หน้าแรก: หัว (โลโก้+ชื่อ+สอศ.) · หุ่น+ข้อความต้อนรับ · เวลา+อากาศจริง · ปุ่ม 8 ปุ่ม · ปุ่มคู่มือ/แบบประเมิน · สโลแกน+QR เว็บวิทยาลัย
- ปุ่ม 8 ปุ่ม:
  1. ข้อมูลพื้นฐาน → แผง: ข่าวเด่น 2×2 (ข่าวจริงจากหน้า admin) + ปุ่ม 8 อัน: ปฏิทินแนะแนว, คลังภาพกิจกรรม, ประวัติ, สาขา, ผลงาน, แผนผัง, ผอ.สอจ.สระบุรี, ช่องทางติดต่อ
  2. ระบบรับสมัครเรียน → เปิดเว็บจริงในจอ `https://tctatc.github.io/thaluang-admission/`
  3. ระบบบริการนักเรียน (TLMis) → `https://tl-mis.vercel.app/login` (ดู "ข้อจำกัด")
  4. ระบบทุนการศึกษา → `https://thaluangcementhaianusorn.github.io/scholarship-system/`
  5. ระบบจองห้องประชุม → `https://tctatc.github.io/nasakorn-thaluang-room-booking2/#/`
  6. ทัวร์วิทยาลัย 3 มิติ → หน้าทัวร์เดิม
  7. สอบถามน้องทานตะวัน → หน้าแชทเต็มจอ (ปุ่มเด่นสุด)
  8. เมนูอื่นๆ → ที่เที่ยว, ร้านอาหาร, คาเฟ่, ที่พัก, ตลาด, ของฝาก (เมนูเดิมจาก `/menu`)
- เว็บระบบภายนอกเปิดเต็มจอ มีแถบบนสีตามปุ่ม + ปุ่ม "กลับหน้าแรก"
- ทุกความสามารถเดิมยังทำงาน: แชท, ไมค์/ตัวหนังสือสด, เสียงพูด, ทักทาย+แขนโบก, ให้ดาว, ข่าวอ่านออกเสียง, วิดีโอหน้ารอ, ประกาศตามเวลา, ป้ายเน็ต, คีย์บอร์ดบนจอ, เครื่องสแกน QR, ปุ่ม GPIO
- ไม่มีคนใช้ตามเวลาที่ตั้ง → ปิดเว็บที่เปิดอยู่ ล้างแชท กลับหน้าแรก แล้วเข้าวิดีโอหน้ารอ (ของเดิม)

## ไม่ทำ (รอบนี้)
- ไม่แก้/ไม่ลบหน้าแนวนอนเดิม (`screen.html`) — ต้องสลับกลับได้ทันทีถ้าหน้าใหม่มีปัญหาวันแข่ง
- ไม่ทำโหมดภาษาอังกฤษบนหน้าใหม่ (ของเดิมก็ปิดอยู่ `lang = "th"`)
- ไม่ทำภาพประกอบหุ่น/รูปวิทยาลัยจริง จนกว่าผู้ใช้ส่งรูปมา (ใช้หุ่น SVG จากม็อกอัปไปก่อน)

## ห้ามเกิด (anti-goals)
- กรรมการกดแล้วเจอจอขาว/จอว่าง/ค้าง
- คนถัดไปเห็นบทสนทนาหรือข้อมูลล็อกอินของคนก่อน
- หน้าใหม่ทำให้ฟีเจอร์เดิมพัง

## ข้อจำกัด
- **TLMis ห้ามเปิดซ้อน** (`X-Frame-Options: DENY`, `frame-ancestors 'none'`) — ถ้ายังไม่มีคนแก้ฝั่ง TLMis
  ปุ่ม 3 ต้องไม่เปิด iframe แต่ขึ้นแผง QR + ข้อความ "สแกนเปิดในมือถือ" (ตั้งค่าต่อระบบว่า `embed: false`)
- คีย์บอร์ดในหน้าเว็บเรา (`osk.js`) พิมพ์ลงเว็บคนละโดเมนใน iframe ไม่ได้ — ต้องหาคีย์บอร์ดระดับระบบบน Pi (งานตรวจสอบแยก)
- ข้อมูลล็อกอินในเว็บที่ฝัง: หน้าเราล้างข้ามโดเมนไม่ได้ — ต้องหาทางล้างระดับเบราว์เซอร์ (งานตรวจสอบแยก)
- Pi 5 วาดจอ 1080p — แอนิเมชันวนตลอดกิน CPU (เคยวัด ~65%) → แอนิเมชันตกแต่งต้องเล่นเป็นช่วงแบบ `body.anim-on` ของเดิม ห้าม `backdrop-filter`

## แนวทางที่พิจารณา
| แนวทาง | ข้อดี | ข้อเสีย |
|---|---|---|
| **A. หน้าใหม่แยก `screen_v.html` ใช้สคริปต์เดิม (เลือก)** | หน้าเดิมไม่โดนแตะ สลับกลับได้ด้วยค่าตั้งเดียว · ใช้ `screen.js`/`news.js`/`extras.js`/`osk.js` ซ้ำ โดยคง id ที่สคริปต์อ้าง | ต้องมีสคริปต์เชื่อม (`portrait.js`) คุมการสลับหน้า |
| B. แก้ `screen.html` ให้รองรับสองแนวด้วย CSS | ไฟล์เดียว | ไฟล์ผูกกับ `screen.js` แน่น พังง่าย เสี่ยงหน้าเดิมพังใกล้วันแข่ง |
| C. เขียนหน้าใหม่ทั้งหมดรวมสคริปต์ | อิสระเต็มที่ | ต้องเขียนไมค์/เสียง/แชทใหม่ ไม่ทันเวลา และเสี่ยงบั๊ก |

ผู้ใช้เลือก A

## การออกแบบ (สิ่งที่ตัดสินแล้ว)
- **เส้นทาง:** `/screen-v` ส่ง `screen_v.html` เสมอ; `/` และ `/screen` ส่งตามค่า `SCREEN_LAYOUT` ใน `config.py`
  (`"landscape"` ค่าเริ่ม = หน้าเดิม, `"portrait"` = หน้าใหม่) — สลับหน้าด้วยการแก้ค่าเดียว
- **โครงหน้า `screen_v.html`:** คง id ทุกตัวที่ `screen.js` และ `news.js` อ้าง (`chat`, `scroll`, `composer`, `q`, `mic`, `stopTalk`,
  `allMenuTpl`, `announce`, `announceText`, `attract`, `vidProg`, `tourView`, `lightbox`, `net`, `.led-text`,
  `clock`, `hello`, `today`, `weather`, `topRow`, `wxIcon`, `wxTemp`, `wxText`, `newsGrid`, `pager`, `home`,
  `board`, `boardIcon`, `boardTitle`, `boardSub`, `boardBody`, `boardAuto`) — ตำแหน่งต่างได้ แต่ต้องมีครบ
- **สามมุมมอง** คุมด้วย class บน `body`: `view-home` (เมนู), `view-chat` (แชทเต็มจอ), และแผง `board`
  - แผง `board` (แผนผัง/รูป/เมนูที่เที่ยว/ปฏิทิน/คลังภาพ/แบบประเมิน/ผอ.): ตอนอยู่หน้าแชท = ครึ่งบนของหน้าแชท
    (แชทเห็นอยู่ด้านล่าง), ตอนอยู่หน้าแรก = แผงซ้อนเต็มจอมีปุ่มกลับ
  - แผงข้อมูลพื้นฐาน (ข่าว + 8 ปุ่ม) และแผงเมนูอื่นๆ เป็นแผงของหน้าใหม่เอง (ไม่ใช่ `board`)
- **`portrait.js` (สคริปต์เชื่อม, โหลดหลัง `screen.js`):**
  - สลับไปหน้าแชทเมื่อมีข้อความผู้ใช้ใหม่ใน `#chat` (พิมพ์, พูด, แตะชิปคำถาม, แตะข่าว, สแกน QR) — ดูจาก MutationObserver
  - ห่อ `newChat` (ฟังก์ชันส่วนกลางของ `screen.js`) ให้กลับหน้าแรกด้วย → การล้างแชทตอนไม่มีคนใช้กลับหน้าแรกเอง
  - ปุ่มระบบภายนอกเปิดด้วย `openTour(url)` เดิม (นับเวลาว่างแบบลิงก์ภายนอก 15 นาที) แต่ปรับแถบบนให้มีชื่อระบบ+สีตามปุ่ม
    ระบบที่ `embed: false` → ขึ้นแผง QR แทน
  - ปุ่มกลับหน้าแรก = ปิดเว็บ/แผงทั้งหมด หยุดเสียง ไม่ล้างแชท (ล้างตอนหมดเวลา/กด "คุยใหม่")
- **รายชื่อระบบภายนอก** เก็บในตัวแปรเดียวใน `portrait.js` (ชื่อ, คำอธิบาย, URL, สี, ไอคอน, `embed`) — แก้ลิงก์ที่เดียว
- **ไอคอน:** ชุด SVG symbol ในหน้า (ไอคอนเส้นแบบ Lucide) ไม่มีอีโมจิในหน้าใหม่;
  ข้อความจาก `screen.js` ที่มีอีโมจิ (เช่น `intro`, `seeLeft`, ป้าย 🎤) — `portrait.js` เขียนทับค่าใน `T.th` ด้วยข้อความไม่มีอีโมจิ
- **ข่าว:** `news.js` วาดการ์ดลง `#newsGrid` ในแผงข้อมูลพื้นฐาน; CSS ของหน้าใหม่จัดการ์ดให้เข้าดีไซน์;
  การ์ดข่าวที่ไม่มีรูปมีอีโมจิใน `news.js` (`big`) → ซ่อนด้วย CSS ในหน้าใหม่
- **อากาศ/เวลา:** ใช้ `news.js` เดิม (`/weather`); id `wxIcon` อยู่ในการ์ดอากาศน้ำเงิน
- **บน Pi:** หมุนจอสัมผัส HDMI-A-2 เป็นแนวตั้ง (`wlr-randr --transform 90/270` ใน `start.sh`) และแมปการสัมผัสกับจอนั้นใน labwc
  (`<touch mapToOutput="HDMI-A-2"/>`) — ต้องทดสอบกับจอจริง

## ยกให้ผู้ลงมือตัดสินเอง
- ตัวเลขระยะ/ขนาดละเอียด (ยึดม็อกอัป)
- วิธีแสดงแผงข้อมูลพื้นฐานเมื่อข่าวว่าง (ใช้การ์ดชวนคุยของ `news.js` ได้)
- รายละเอียดแอนิเมชัน (ต้องเล่นเป็นช่วงตาม `anim-on`)

## งานตรวจสอบบน Pi (ต้องเสียบจอสัมผัส)
1. หมุนจอ + การสัมผัสตรงจุด
2. คีย์บอร์ดระบบที่ลอยทับ kiosk ได้ (ลอง `wvkbd` หรือ squeekboard แบบ layer overlay) เพื่อพิมพ์ในเว็บที่ฝัง
3. ล้างข้อมูลล็อกอินของเว็บที่ฝังตอนกลับหน้าแรก/หมดเวลา (เช่น ให้เซิร์ฟเวอร์สั่งเบราว์เซอร์ผ่าน remote debugging ล้าง storage ของโดเมนเหล่านั้น หรือรีสตาร์ต kiosk ตอนไม่มีคนใช้)
